title: "Troubleshooting"
description: "Fix the most common recording, transcription, and summary problems."
---

## Audio is missing

Open **Settings → Permissions** and confirm:

- **Microphone** is allowed so Librelog can hear you.
- **System Audio** is allowed so Librelog can hear the other people on the call.

If a permission is denied, use **Open** to change it in your operating system's settings, then restart Librelog.

On Linux, confirm that your desktop audio service can see the microphone and the output-monitor source. On Windows or Linux, include the app and operating-system versions if audio works in other apps but not in Librelog.

A recording warning identifies an unavailable microphone or system-audio source. Check the device connection and permissions, then use **Retry** to restart the failed source without stopping the recording. Librelog keeps capturing the source that still works. Audio missed while a source was unavailable cannot be recovered by retrying.

## The transcript is not live

Open **Settings → Transcription** and check the selected model. **Live** models transcribe during the meeting. **After recording** models wait until you stop.

If transcription fails, confirm the provider is configured, the model supports your spoken languages, and a local provider is running.

## No summary appears

A summary needs an Intelligence model. Open **Settings → Intelligence**, then select a local runtime or configure a provider with your own API key.

For LM Studio and Ollama, confirm the local server is running. See [Transcription and AI](/ai-setup).

## A recording disappeared

Open **Settings → Meetings** and check **Audio file retention** under **Audio**. Librelog can delete audio immediately or after a selected period while keeping the note and transcript.

See [Data, privacy, and retention](/data-and-privacy#choose-how-long-audio-is-kept) for every retention option.

## An imported file does nothing

Audio imports accept WAV, MP3, OGG, MP4, M4A, FLAC, WebM, and AAC. Transcript imports accept SRT and VTT.

For audio, confirm that a Transcription model is selected and that a local provider is running. See [Import audio or a transcript](/import-recordings).

## Meeting-history import shows no apps

Librelog lists supported meeting assistants it detects on your computer. Open the source app, restart Librelog, and return to **Settings → Imports**.

If you already removed the source app, reinstall it long enough to complete the import or export the transcript as SRT or VTT and [import it into an empty note](/import-recordings#import-a-transcript).

## Chat has no meeting context

Open the meeting before opening Chat and wait for its transcript or summary to finish. The open meeting is added automatically when its content is available. If Chat still answers without it, start a new chat from that meeting and name the meeting in your request. If no Intelligence model is configured, open **Settings → Intelligence**.

See [Chat with your meetings](/chat) for context guidance and example requests.

## An automation did not run

Open **Automations**, select the automation, and check whether it is enabled and what its last run reports. Confirm that:

- The export folder is selected and still exists.
- The folder is writable.
- The meeting finished and produced the content the automation needs.
- Librelog was open when the meeting ended.

See [Automate meeting follow-up](/automations).

## The app does not open after installation

Confirm that you downloaded the DMG for your Mac's chip. Release builds are not notarized, so macOS blocks the first launch: right-click Librelog in **Applications** and choose **Open**, or run:

```bash
xattr -dr com.apple.quarantine /Applications/Librelog.app
```

On Linux, make an AppImage you built executable before opening it, or install a DEB you built with `sudo apt install ./librelog-*.deb` so the package manager can resolve dependencies. See [Install the desktop app](/desktop-installation).

## Linux opens a black window and plays music

First launch opens the setup screen and plays quiet background music. A black window with loud or looping audio usually means WebKitGTK failed to paint, most often on Wayland with NVIDIA.

Current builds disable the WebKit DMA-BUF renderer automatically. If the window is still black, launch with:

```bash
WEBKIT_DISABLE_DMABUF_RENDERER=1 WEBKIT_DISABLE_COMPOSITING_MODE=1 librelog
```

The same variables work for an AppImage. See [Install the desktop app](/desktop-installation).

## Get more help

[Open a GitHub issue](https://github.com/Arturgrr/librelog/issues). Report security vulnerabilities privately as described in [Security](/security#report-a-vulnerability).

Include your operating system, Librelog version, the exact error, what you expected, and the shortest steps that reproduce the problem. For AI failures, include the selected provider and model.

<Warning>
  Never include API keys, meeting content, or other private data when reporting a problem.
</Warning>

For CLI and MCP errors, use the [error reference](/reference/errors).
