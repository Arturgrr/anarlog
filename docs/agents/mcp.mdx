---
title: "MCP for agents"
description: "Connect an MCP client to Librelog meeting context over local stdio."
---

The `librelog` executable includes a local MCP server. It communicates over standard input and output, opens no port, and reads the database on your computer. No account or network connection is needed.

## Configure the client

[Install the CLI](/installation), then open the desktop app once so it can create the database. The app does not need to stay open after that.

Add the server to your MCP client:

```json
{
  "mcpServers": {
    "librelog": {
      "command": "librelog",
      "args": ["mcp"]
    }
  }
}
```

In the desktop app, **Settings → Developers → MCP server → Copy config** copies a ready-made configuration once the CLI is installed.

In Claude Code, you can add the same server from a terminal:

```bash
claude mcp add librelog -- librelog mcp
```

If `librelog` is not on the client's `PATH`, use the executable's absolute path as `command`. Restart the client after changing its configuration.

For a custom database path:

```json
{
  "mcpServers": {
    "librelog": {
      "command": "librelog",
      "args": ["--db-path", "/path/to/app.db", "mcp"]
    }
  }
}
```

## Use tools deliberately

Start with `list_meetings`, then pass a returned `id` to `get_meeting`. Call `get_meeting_transcript` only when the notes and summaries do not answer the question. Report only meetings the tools return. An empty search only establishes that no meetings matched; do not invent titles.

A meeting's `updated_at` is a content-change timestamp. Report database errors instead of hiding them.

Transcript pages default to 200 words and cap at 500. Follow `pagination.next_offset` only when you need more context.

Use `get_recurring_meeting_history` with a known meeting ID when a task depends on earlier meetings in the same series. Use `export_meeting` only when the task explicitly needs the complete record including transcripts.

To persist an edit, use `propose_summary_edit` or `propose_memo_edit`. The tool returns a pending proposal. Do not claim the meeting changed. Use `list_proposals` and `get_proposal` to inspect staged work. `decline_proposal` discards a pending proposal; applied or already-declined proposals cannot be declined.

Use `import_recording` only when the user explicitly asks to import a recording. The desktop app must be open. Poll `get_recording_import` for the result.

The server also exposes MCP resources (`librelog://meetings/...`) for Markdown or plain-text context when the client prefers resources over tools.

See the [MCP reference](/reference/mcp) for exact parameters and resources.
