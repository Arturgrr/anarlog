# Security Policy

## Supported Versions

Security fixes are applied to the latest release only, including beta releases such as `0.1.0-beta.N`.

| Version                         | Supported          |
| ------------------------------- | ------------------ |
| Latest release (beta or stable) | :white_check_mark: |
| Older versions                  | :x:                |

If you're on an older version, update to the latest release before reporting an issue you can no longer reproduce.

## Reporting a Vulnerability

Please do not open a public issue for security vulnerabilities.

Report it privately through [GitHub Security Advisories](https://github.com/Arturgrr/librelog/security/advisories/new) on this repository.

When reporting, please include:

- A description of the vulnerability and its potential impact
- Steps to reproduce, a proof of concept, or affected code paths
- The Librelog version and platform you tested against

## What to Expect

This fork is maintained by an individual, so response times are best effort.

- You'll get an acknowledgement on the advisory once the report has been read.
- You'll be kept updated while it is investigated, and told whether the report is accepted or declined.
- If accepted, the fix will credit you in the release notes unless you prefer to stay anonymous.
- Please allow a reasonable window for a fix before any public disclosure.

Vulnerabilities in code inherited from [fastrepl/anarlog](https://github.com/fastrepl/anarlog) may also affect upstream; consider reporting them there too.
